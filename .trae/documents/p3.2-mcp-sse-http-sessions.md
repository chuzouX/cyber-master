# P3.2 MCP SSE/HTTP 客户端 + Session 系统

## Context

P3 已完成 MCP **stdio** 客户端 + Skill + 统一工具表。当前遗留两点：

1. `McpTransport::Sse` / `McpTransport::Http` 在 `servers.toml` 可解析，但 `registry.rs::connect_one` 直接返回 `UnsupportedTransport` 跳过（[registry.rs:135-148](../../crates/cyber-mcp/src/registry.rs)）。需补齐这两种远程传输客户端。
2. 对话历史按 cwd 单文件存储（`~/.cyber/history/{cwd_hash}.json`，[history.rs](../../crates/cyber-tui/src/history.rs)），无 session 概念。需支持多 session：`/new` 新建、`/sessions` 面板切换/新建/删除、session 间对话独立、`/sessions read` 跨 session 读取（仅同 cwd）。

目标：补齐 MCP 两种传输 + 落地多 session 管理，全部 build/clippy/test 全绿，DESIGN/PROGRESS 同步。

## Part A — MCP SSE + Streamable HTTP 客户端

### A.1 架构决策（复用现有 actor 接口）

`McpConnection`（[connection.rs:56-61](../../crates/cyber-mcp/src/connection.rs)）本身**传输无关**：只持 `tx: UnboundedSender<McpRequest>` + `next_id` + `tools`。`call()` / `handshake()` / `call_tool()` 全走 `tx` channel + oneshot，与传输无关。现有 `actor_loop` 是**长连接双工流**模型（read_line 循环 + write），适配 stdio；但 HTTP 是**每次调用一个 POST**，不适配该循环。

**方案**：保留 `McpConnection` 与 `McpRequest` 不变，新增两个 spawn 函数，各自起一个**不同的 actor 实现**处理同一 `McpRequest` 流：
- `McpConnection::spawn_http(spec)` → 起 `http_actor_loop`（每次 call 一个 reqwest POST）
- `McpConnection::spawn_sse(spec)` → 起 `sse_actor_loop`（长连 GET event-stream 收响应 + 每次 call POST 到 endpoint）

两者握手仍复用 `McpConnection::handshake()`（经 `call()` + `send_notification()`，与 stdio 一致）。`connect_one` 改为按 transport 分派到三个 spawn 函数。

### A.2 新模块 `cyber-mcp/src/sse.rs`（SSE 事件解析，两种传输共用）

- `pub struct SseEvent { pub event: String, pub data: String }`
- `pub struct SseParser`（增量状态机：feed `&[u8]` → 产出 `Vec<SseEvent>`；按 `\n` 切行，`event:`/`data:` 前缀分派，空行触发事件派发；支持 `\r\n` 与多行 `data:` 拼接）
- `pub fn parse_sse_text(text: &str) -> Vec<SseEvent>`（对完整 body 一次性解析，供 HTTP event-stream 响应用）
- `pub fn extract_jsonrpc_responses(events: &[SseEvent]) -> Vec<JsonRpcResponse>`（从 `event: message` 或默认事件的 data 里抽 JSON-RPC 响应）

### A.3 `proto.rs` 微调（notification 规范化）

当前 `JsonRpcRequest::new(0, method, params)` 用 id=0 模拟 notification（[connection.rs:272](../../crates/cyber-mcp/src/connection.rs)）。HTTP/SSE 需要无 id 的真 notification。改 `JsonRpcRequest.id: Option<u64>` + `#[serde(skip_serializing_if = "Option::is_none")]`：
- `JsonRpcRequest::new(id, method, params)` → `id: Some(id)`（序列化不变 `"id":N`，现有 `call_roundtrip` 测试 `req.id == Some(0)` 仍过）
- 新增 `JsonRpcRequest::notification(method, params)` → `id: None`（序列化省略 id 字段）
- stdio actor 的 notification 改用 `notification()`（id=0→无 id，更规范；route_response 本就忽略无 pending 的响应，无影响）

### A.4 `connection.rs` 新增 `spawn_http` + `http_actor_loop`（Streamable HTTP）

```
pub async fn spawn_http(spec: &McpServerSpec) -> Result<(Arc<Self>, JoinHandle<()>)>:
  url = spec.url.ok_or(InitFailed{server, "http 缺 url"})?
  client = reqwest::Client::builder().timeout(Duration::from_secs(timeout)).build()?
  headers = expand_env_headers(&spec.headers)  // ${VAR} → env 展开
  (tx, handle) = start_http_actor(client, url, headers)
  conn = Self { server_name, tx, next_id:0, tools:[] }
  tools = tokio::time::timeout(Duration::from_secs(timeout), conn.handshake()).await (同 spawn_stdio)
  Ok((Arc::new(conn{tools}), handle))
```

`http_actor_loop(client, url, headers, mut rx)`：
- 维护 `session_id: Option<String>`（Streamable HTTP 在 initialize 响应头 `Mcp-Session-Id` 下发，后续请求须回带）
- `Call { id, method, params, reply }`：
  - `reqb = client.post(url).header(CONTENT_TYPE,"application/json").body(serde_json::to_vec(&JsonRpcRequest::new(id,method,Some(params)))?);` 加 headers + `mcp-session-id`（若有）
  - `resp = reqb.send().await`；失败 → `reply.send(Err(McpError::Network))`
  - 从 `resp.headers()` 取 `mcp-session-id` 更新 `session_id`（initialize 时设置）
  - 按 Content-Type 分派：
    - `text/event-stream` → `tokio::time::timeout(CALL_TIMEOUT, resp.text())` → `parse_sse_text` → `extract_jsonrpc_responses` → 取 `id` 匹配者 → reply Ok(result)/Err(Rpc)
    - 否则（`application/json` 等）→ `resp.json::<JsonRpcResponse>()` → reply Ok/Err
- `Notification { method, params }`：POST `JsonRpcRequest::notification(...)`，忽略响应体（best-effort，失败仅 warn）
- `Shutdown`：break（reqwest::Client drop 即关闭连接池）

### A.5 `connection.rs` 新增 `spawn_sse` + `sse_actor_loop`（legacy SSE）

```
pub async fn spawn_sse(spec) -> Result<(Arc<Self>, JoinHandle<()>)>:
  sse_url = spec.url?
  client = reqwest::Client::builder().build()?  // 不设全局 timeout（长连流）
  headers = expand_env_headers(&spec.headers)
  (tx, handle) = start_sse_actor(client, sse_url, headers)
  conn = Self {...}
  tools = timeout(timeout, handshake).await??
  Ok((Arc::new(conn), handle))
```

`sse_actor_loop(client, sse_url, headers, mut rx)`：
- `resp = client.get(sse_url).headers(headers).send().await?`，校验 `text/event-stream`
- 共享状态：`pending: Arc<Mutex<HashMap<u64, oneshot::Sender>>>`、`endpoint: Arc<Mutex<Option<String>>>`、`shutdown = AtomicBool`
- 派生 reader task：把 `resp.bytes_stream()`（`futures::StreamExt`）喂给 `SseParser`：
  - `event: endpoint` → data 是 POST URL（相对则按 `sse_url` resolve）→ 存 `endpoint`
  - `event: message`/默认 → `extract_jsonrpc_responses` → 按 id 从 `pending` 取 oneshot 回执（Ok/Err），无匹配 id 忽略
  - 流结束/出错 → fail 所有 pending（ChannelClosed）+ 设 shutdown
- 主循环 `while let Some(req) = rx.recv().await`：
  - `Call { id, method, params, reply }`：等 `endpoint` 就绪（轮询/notify）→ `pending.insert(id, reply)` → POST `JsonRpcRequest::new(id,...)` 到 endpoint；POST 失败 → `pending.remove(id)` + reply Err(Network)。响应由 reader task 异步回填。
  - `Notification` → POST `notification(...)` 到 endpoint
  - `Shutdown` → 置 shutdown + abort reader + break

### A.6 `error.rs` 新增变体

- `Network { server: String, detail: String }`（reqwest 请求失败，from `reqwest::Error` 用 `#[from]` 或手动包，避免与现有 `Io` 混淆）
- `BadResponse { server: String, detail: String }`（响应解析失败 / Content-Type 非 JSON 且非 SSE）

### A.7 `registry.rs::connect_one` 分派

```rust
match spec.transport {
    McpTransport::Stdio => McpConnection::spawn_stdio(spec).await,
    McpTransport::Http  => McpConnection::spawn_http(spec).await,
    McpTransport::Sse   => McpConnection::spawn_sse(spec).await,
}
```
`McpRegistry::connect_all` / `shutdown_all` 无需改（对 Sse/Http 的 `JoinHandle` 同样 await；SSE 的 reader abort 在 actor 内部 Shutdown 处理）。

### A.8 配置/环境变量展开

新增 `fn expand_env_headers(headers: &HashMap<String,String>) -> HeaderMap`（在 connection.rs 或 config.rs）：`${VAR}` → `std::env::var("VAR")`，未设置则空串。使 `default_mcp_servers.toml` 示例 `Authorization = "Bearer ${MCP_TOKEN}"` 实际生效。stdio 的 `env` 保持原样不展开（与现状一致）。

### A.9 `Cargo.toml`

`crates/cyber-mcp/Cargo.toml` 加 `reqwest = { workspace = true }`（workspace 已含 `rustls-tls/json/stream` features，够用）。

### A.10 测试

- `sse.rs` 单元测试：`SseParser` 增量分片、`\r\n`、多行 `data:`、`event:` 分派；`parse_sse_text` / `extract_jsonrpc_responses` 纯函数测试。
- `expand_env_headers` 单元测试（`${VAR}` 展开 / 未设置→空）。
- `connection.rs` 新增 `#[tokio::test]` HTTP e2e：用 `tokio::net::TcpListener` 起本地 HTTP，串行回 `initialize`（带 `Mcp-Session-Id` 头）/`tools/list`/`tools/call` 三个 JSON 响应，断言握手拿到 1 个工具 + `call_tool` 返回 content + 后续请求回带了 session id。
- SSE e2e：本地 server GET `/sse` 发 `event: endpoint\ndata: /msg\n\n` 后，对每个 POST `/msg` 回 `event: message\ndata: {jsonrpc响应}\n\n`，断言握手 + call roundtrip。
- 既有 24 个 mcp 测试全保留（proto.id 改 Option 不破坏 `call_roundtrip` 的 `req.id == Some(0)`）。

## Part B — Session 系统（同 cwd 内多 session）

### B.1 存储模型 + 迁移

新布局（`history.rs` 重写）：
```
~/.cyber/history/{cwd_hash}/
  index.json     # { "current": "<id>", "sessions": [SessionMeta] }
  {id}.json      # Vec<ChatEntry>
```
- `SessionMeta { id: String, title: String, created_at: u64, updated_at: u64, message_count: usize }`（serde）
- `SessionIndex { current: String, sessions: Vec<SessionMeta> }`

**迁移**（`load_index`）：若 `{cwd_hash}/index.json` 不存在但旧 `{cwd_hash}.json` 存在 → 建 1 个 session（id 新生成、title 从首条 User 消息截断或 "默认会话"、message_count=len），写 `index.json` + `{id}.json`，旧文件 rename 为 `.legacy.bak`。无旧文件 → 建默认空 session（title "新会话"）。

**id 生成**：`SystemTime` 纳秒 → base36（短、唯一），如 `lr3k2xqf`。无新依赖。

### B.2 `history.rs` 新 API（替换旧 load/save）

- `pub fn session_dir(history_dir, cwd) -> PathBuf`
- `pub fn load_index(history_dir, cwd) -> SessionIndex`（含迁移）
- `pub fn save_index(history_dir, cwd, &SessionIndex)`
- `pub fn load_entries(history_dir, cwd, id) -> Vec<ChatEntry>`（文件缺失/损坏→空）
- `pub fn save_entries(history_dir, cwd, id, &[ChatEntry])`（原子 tmp→rename，建目录）
- `pub fn create_session_meta() -> SessionMeta`（新 id + "新会话" + now）
- `pub fn load_current(history_dir, cwd) -> (SessionIndex, Vec<ChatEntry>)`（启动用：取 index.current 的 entries）
- `pub fn save_current(history_dir, cwd, &mut SessionIndex, &[ChatEntry])`（写当前 session 文件 + 刷新 meta：message_count、updated_at、title 派生）
- `pub fn list_sessions(history_dir, cwd) -> Vec<SessionMeta>`（供 `/sessions read` 无参列举）
- `pub fn read_session_text(history_dir, cwd, id) -> Option<String>`（格式化 User/Assistant 为文本，供 `/sessions read`）
- `pub fn delete_session(history_dir, cwd, id)`（删 `{id}.json` + 从 index 移除）

**title 派生**：`save_current` 时若 meta.title=="新会话" 且 entries 首条为 User → title = 首 40 字符。

旧 8 个测试重写为新 API（迁移、隔离、save/load 往返、删空覆盖、损坏回退空、id 文件名）+ 新增 session 隔离/迁移/删除测试。

### B.3 `App` 状态 + 启动/保存

`app.rs` `App` 新增字段：
- `sessions: SessionIndex`（current + items，内存镜像）
- `sessions_panel: SessionsPanelState`（面板状态：`selected: usize`、`pending_delete: Option<usize>`、进入时刷新的 `list`）

`App::run()`（[app.rs:222-230](../../crates/cyber-tui/src/app.rs)）：
- 旧 `let saved = history::load(...)` → `let (index, entries) = history::load_current(history_dir, cwd); self.sessions = index; self.chat.entries.extend(entries);`
- `seed_input_history()` 保留。

`App::save_history()`（[app.rs:259-261](../../crates/cyber-tui/src/app.rs)）：
- → `history::save_current(history_dir, cwd, &mut self.sessions, &self.chat.entries)`（含 title 派生）

### B.4 Session 切换/新建/删除（核心操作）

抽 `App` 方法（均流式期阻止，与 /mode 一致）：
- `switch_session(&mut self, id: &str)`：`save_history()`（存当前）→ `entries = load_entries(id)` → `self.chat = ChatState::new()` + `entries` + `seed_input_history()` → `self.sessions.current = id` → `save_index()` → toast。
- `create_session(&mut self)`：`save_history()` → `meta = create_session_meta()` → `self.sessions.sessions.push(meta.clone())` → `self.sessions.current = meta.id` → 新空 `ChatState` → `save_index()` + `save_entries(空)` → toast "新会话已创建"。
- `delete_session(&mut self, id: &str)`：若仅 1 个 session → toast 拒绝；若删的是 current → 切到剩余首个；`delete_session(id)` + 从 `self.sessions.sessions` 移除 + `save_index()`。

`spawn_agent` 不变（`self.chat.history()` 天然只含当前 session）→ 独立性自动保证。

### B.5 斜杠命令（`slash.rs` + `app.rs::handle_slash_command`）

`slash.rs` `COMMANDS` + `SlashCommand` + `parse` + `HELP_TEXT` 新增：
- `New` — `/new`（无参），desc "新建会话"
- `Sessions(String)` — `/sessions <list|read <id|关键词>|new>`，desc "会话管理：list 面板 / read 跨会话读取 / new 新建"

`handle_slash_command` 新增分支：
- `SlashCommand::New` → 流式期阻止；否则 `create_session()`。
- `SlashCommand::Sessions(args)` → `handle_sessions_slash(args)`：
  - `""` / `list` → `self.sessions_panel.refresh(&self.sessions); self.prev_mode = Chat; self.mode = Mode::Sessions;`
  - `read`（无参）→ 列出所有 session（id+title+count）为 System 条目
  - `read <id|关键词>` → 精确 id 命中 → `read_session_text` → push `ChatEntry::System(format!("📖 会话「{title}」内容：\n{text}"))`；无命中/多命中 → 提示候选。**仅展示，不入 agent history**（System 条目被 `history()` 剥离，保持 session 独立）。
  - `new` → 同 `/new`
  - 未知子命令 → 用法提示

### B.6 `/sessions` 面板（`Mode::Sessions` + `views/sessions.rs`）

`app.rs` `Mode` 加 `Sessions` 变体 + `label()` "Sessions"。

`views/mod.rs` 加 `pub mod sessions;`。`views/sessions.rs::render(frame, area, theme, &SessionsPanelState, &SessionIndex)`：列表渲染（title + message_count + id + 当前 `★` 标记 + 待删除 `✗?` 提示），底部 hint。

`SessionsPanelState`（`app.rs` 或新 `sessions.rs`）：
- `selected: usize`、`pending_delete: Option<usize>`、`list: Vec<SessionMeta>`（进入时快照）
- `refresh(&mut self, idx: &SessionIndex)`：克隆 `sessions` 到 `list`，`selected` 指向 `current`

`app.rs::handle_event`（[app.rs:312-319](../../crates/cyber-tui/src/app.rs)）新增 `Mode::Sessions => self.handle_sessions_key(k)`。

`handle_sessions_key(k: KeyEvent)`（仿 `handle_provider_form_key`，直接处理原始键，不污染 `Action` 枚举）：
- `Up/Down` → 移 `selected`（在 `list.len()` 内循环）
- `Enter` → 切换到选中：`switch_session(list[selected].id)` + `mode = Chat`
- `n` → `create_session()` + `mode = Chat`
- `d` → 删除确认：首次 `d` 设 `pending_delete=Some(selected)`；二次 `d`（同一项）执行 `delete_session` + 刷新面板；其它键清 `pending_delete`
- `Esc` → `mode = Chat`（不切换）
- `q` / `Ctrl+C` → `should_quit`

`render_main`（[app.rs:1254-1302](../../crates/cyber-tui/src/app.rs)）加 `Mode::Sessions => views::sessions::render(...)`。`render_status_bar` 加 Sessions 提示 `↑↓ 选  Enter 切换  n 新建  d 删除  Esc 返回`。`handle_action` 的 `Tab`/`Esc` 分支把 `Sessions` 当作与 `Settings`/`ProviderForm` 同级的模态层（Tab 不循环到它，Esc 返回 Chat）。

### B.7 `make_app` 测试 helper 更新

所有 cyber-tui app 测试的 `make_app` 构造处加 `sessions: SessionIndex::default_single()`（或 `load_current` 于 tempdir）+ `sessions_panel: SessionsPanelState::default()`。新增 app 测试：`/new` 创建并切、`/sessions` 进面板、面板 Enter 切换、`d` 删除（单 session 拒绝）、`/sessions read` 跨读注入 System。

## 已知范围/限制

- 跨 session 读取**仅同 cwd**；`/sessions read` 注入为 System 条目（展示用，不入 agent history，保持独立）。
- HTTP event-stream 响应用 `resp.text()` + 调用级 timeout 读取（v0.1 不支持服务器长连持续推送）。
- SSE 为 deprecated 传输，实现功能但测试以解析单测 + 单 e2e 为主。
- 不引入 chrono：时间戳用 `SystemTime` 纳秒，面板不显示格式化时间（仅 title/count/当前标记）。
