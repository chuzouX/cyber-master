# P2.2 实现计划 — 工具调用 + Agent Loop + 斜杠命令 + Generation 计数器

## Context

P2 核心流式对话已完成（Provider trait + OpenAI/Anthropic/Ollama/Mock 流式 + tokio 事件总线 + ChatView）。当前 `agent.rs::run_stream` 是**单次直通**：流式输出 token 后即结束，无工具调用、无循环。`cyber-tools` 是空 stub，`StreamEvent` 只有 `Delta/Done/Error`，`Message` 只有 `{role, content}`，stale 事件仅靠 `streaming` bool 兜底。

本 pass 补全 Chat 的**核心闭环能力**（用户已确认范围）：
1. **工具调用协议** — 解析 OpenAI/Anthropic/Mock 的 tool-call 流式 delta，执行工具，结果回灌
2. **Agent loop** — 流式→收集 tool_calls→执行→追加 tool 结果→再流式，循环至无工具调用或 `max_steps`
3. **内置工具** — `read_file` / `write_file` / `list_dir` / `shell`（受 `.cyber.md` rules 护栏约束）
4. **斜杠命令** — `/help /clear /mode /model /tools /cancel /quit`（本地处理，不 spawn agent）
5. **Generation 计数器** — 每次 spawn/cancel 递增，事件携带 gen，TUI 忽略 stale-gen 事件
6. **TUI 工具调用展示** — `[tool] name(args) → result` 内联显示

**明确推迟**：会话历史持久化（SQLite，cyber-storage）、流式重绘性能优化（留下一 pass）。

## 关键设计决策

| 项 | 决策 |
|---|---|
| Tool trait 位置 | 定义在 **cyber-agent**（消费方/loop 驱动），内置工具放 `cyber-agent::tools/`。cyber-agent **不依赖** cyber-tools/mcp/skills，dep 图保持无环；P3/P6 那些 crate 反向依赖 cyber-agent 实现 `Tool` 注入统一工具表 |
| Provider 签名 | 引入 `StreamRequest { messages, system, tools: Vec<ToolSchema> }` 结构体（前向兼容，自文档）；`tools` 空 = 不发 tools 字段（等同当前行为） |
| 工具 delta 解析 | parser 保持**无状态** `fn(&str) -> Vec<StreamEvent>`，每行产出 `ToolCallDelta { index, id?, name?, arguments_fragment }` 片段；**累积状态在 agent loop** 按 index 合并。返回类型由 `Option` 改 `Vec`（一行可能含多个 tool_calls） |
| Generation | 通道类型改为 `(u64, AgentEvent)` 元组（不侵入 AgentEvent 枚举）；spawn 与 cancel 均 bump generation |
| Message 模型 | 增 `Role::Tool`、`Message.tool_calls: Vec<ToolCall>`（assistant）、`Message.tool_call_id: Option<String>`（tool 结果） |
| 跨轮历史 | `ChatState::history()` **只取 User/Assistant 文本**，剥离 ToolCall/ToolResult（工具链仅在单次 spawn 内部维护） |
| Mock 双模 | `req.tools` 空 → 旧行为（回放 `收到：{input}`）；非空 → 触发 tool loop（先发 list_dir tool_call，收到 tool 结果后发最终文本）。保旧测试 + 可测 loop |
| Tool::run | 手写 `Pin<Box<dyn Future + Send + 'a>>`（与 Provider 一致，不引 async-trait） |
| cwd 来源 | App 增 `cwd: PathBuf` 字段（来自 main 的 `cli.cwd`），传入 run_stream → `ToolCtx.cwd`（project.path.parent() 作 fallback） |

## 实现步骤（按编译顺序）

### Step 1 — 扩展核心类型（`types.rs` + 构造点）

**文件**：`crates/cyber-agent/src/types.rs`、`agent.rs`、`tests/mock_roundtrip.rs`、`crates/cyber-tui/src/chat.rs`

- `Role` 增 `Tool` 变体 + `#[derive(Default)]`（默认 User）+ `as_str` 加 `"tool"`
- `Message` 增 `tool_calls: Vec<ToolCall>`、`tool_call_id: Option<String>`（均 `#[serde(default, skip_serializing_if)]`），derive `Default`
- 新增 `ToolCall { id, name, arguments: String }`（arguments 为 JSON 字符串）
- 新增 `ToolCallDelta { index: u32, id: Option<String>, name: Option<String>, arguments_fragment: String }`
- `StreamEvent` 增 `ToolCallDelta(ToolCallDelta)`
- `AgentEvent` 增 `ToolCall { id, name, arguments }` 与 `ToolResult { id, name, output, is_error }`
- **删除** `impl From<StreamEvent> for AgentEvent`（片段无 1:1 映射）
- 增 `Message` 构造器：`user/assistant/system/tool`（用 `..Default::default()`），替换所有 `Message { role, content }` 字面量
- 更新 types.rs 测试（`as_str` 加 Tool；`stream_event_to_agent_event` 改显式 match 或删）

### Step 2 — Tool trait + 注册表 + 内置工具 + 护栏（新文件）

**新文件**：`crates/cyber-agent/src/tool.rs`、`tools/{mod,read_file,write_file,list_dir,shell,guard}.rs`；`lib.rs` 增 `pub mod tool; pub mod tools;`

- `tool.rs`：`ToolSchema { name, description, parameters: serde_json::Value }`、`ToolOutput { content, is_error }`、`ToolCtx { cwd: PathBuf, rules: Vec<String>, scope: Option<String> }`、`trait Tool: Send + Sync`（`schema()` + `run(&self, input, ctx) -> Pin<Box<dyn Future<Output=Result<ToolOutput>> + Send + '_>>`）、`ToolRegistry { tools: Vec<Box<dyn Tool>> }`（`register/schemas/get/execute/with_builtins/is_empty`）
- `tools/guard.rs`：`check_command(cmd, ctx) -> Result<(), String>` + `check_write_path(path, ctx)`。字符串子串 denylist（`rm -rf /`、fork bomb、`shutdown/reboot/halt`、`mkfs`、`dd ...of=/dev/`、`chmod -R 777 /`、`curl|sh` 等）+ scope token 简单匹配（无 regex 依赖）
- 内置工具：`read_file`（`{path}`→内容，~64KB 上限，`std::fs::read`+lossy）、`write_file`（`{path,content}`→写，护栏查路径）、`list_dir`（`{path}`→条目列表）、`shell`（`{command}`→`tokio::process::Command`：Unix `sh -c` / Windows `cmd /C`，捕获 stdout+stderr，护栏先查）
- `tools/mod.rs`：`register_builtins(reg)` + `pub fn builtin_tool_names() -> &'static [&'static str]`
- 无新 Cargo 依赖（tokio full 已含 process）

### Step 3 — Provider `StreamRequest` + parser `Vec<StreamEvent>` + tool delta 解析

**文件**：`provider.rs`、`sse.rs`、`openai.rs`、`anthropic.rs`、`ollama.rs`、`mock.rs`、`agent.rs`（过渡：单次直通，忽略 ToolCallDelta）

- `Provider::stream(&self, req: StreamRequest) -> Pin<Box<dyn Stream>>`
- `HttpStream.parser: fn(&str) -> Vec<StreamEvent>`；`Streaming` 臂 `pending.extend(parser(&line))`
- **OpenAI**：`delta.content`→`Delta`；`delta.tool_calls[]`→每项 `ToolCallDelta{index,id,name,arguments_fragment}`；`[DONE]`→`Done`（**不**在 `finish_reason=="tool_calls"` 发 Done，避免 double-Done）
- **Anthropic**：`content_block_start` type=tool_use → `ToolCallDelta{index,id,name,""}`；`content_block_delta` type=input_json_delta → `ToolCallDelta{index,None,None,partial_json}`；type=text 的 start 为 no-op；`message_stop`→`Done`
- **Ollama**：best-effort（`message.tool_calls` 非空→完整 `ToolCallDelta`），标注非标准
- 请求体：OpenAI/Ollama 非空 tools 加 `"tools":[{"type":"function","function":{name,description,parameters}}]`；assistant 的 tool_calls 序列化；`Role::Tool`→`{role:"tool",tool_call_id,content}`。Anthropic：tools→`"tools":[{name,description,input_schema}]`；assistant tool_calls→`content:[{type:"tool_use",id,name,input:JSON}]`；`Role::Tool`→`{role:"user",content:[{type:"tool_result",tool_use_id,content}]}`（替换原 `filter(!=System)` 为显式按 role 翻译）
- `agent.rs` run_inner 过渡：`StreamRequest{messages,system,tools:vec![]}`，单次循环忽略 `ToolCallDelta`，保持 TUI 可用

### Step 4 — Agent loop + generation + ChatEntry + TUI（最大步，签名互锁）

**文件**：`agent.rs`、`chat.rs`、`app.rs`、`main.rs`、`views/chat.rs`

**4a. `agent.rs`** — `run_stream(..., tx: UnboundedSender<(u64,AgentEvent)>, gen: u64, mock, cwd: PathBuf)`。loop 伪码：
```
provider=factory; system=build_system_prompt; ctx=ToolCtx{cwd,rules,scope}
registry=ToolRegistry::with_builtins()
tools = auto_tool_call && !registry.is_empty() ? registry.schemas() : []
messages = history + [Message::user(user_input)]
for step in 0..max_steps:
    stream = provider.stream(StreamRequest{messages.clone(), system, tools})
    (text, calls:BTreeMap<u32,ToolCall>) = accumulate(stream, tx, gen)  // Delta→tx Token；ToolCallDelta→累积；Done→break
    if calls.is_empty(): messages.push(assistant(text)); tx(Done); return
    messages.push(assistant{content:text, tool_calls:calls.values()})
    for call in calls.values():
        tx(ToolCall{...}); input=serde_json::from_str(args).unwrap_or(Null)
        out = registry.execute(call.name, input, &ctx).await  // 失败→ToolOutput{is_error}
        tx(ToolResult{...}); messages.push(Message::tool(call.id, out.content))
    // 继续循环
tx(Error("超过 max_steps"))
```

**4b. `chat.rs`** — `ChatEntry` 枚举替换 `ChatMessage`：`User/Assistant/ToolCall/ToolResult/System`；`ChatState.entries: Vec<ChatEntry>`。方法：`submit()`（push User，返回 `(text, history())`）、`history()`（仅 User/Assistant→Message）、`flush_streaming_to_assistant()`（buffer 非空→push Assistant，不切 streaming）、`push_tool_call/push_tool_result`（先 flush 再 push）、`finalize_stream/cancel_stream/clear/take_input`

**4c. `app.rs`** — 增 `generation: u64`、`cwd: PathBuf` 字段；`agent_tx` 改 `UnboundedSender<(u64,AgentEvent)>`。`spawn_agent`：bump generation + 传 gen + 传 cwd。`handle_agent_event((gen,ev))`：`gen != self.generation` 直接 return；ToolCall→`push_tool_call`，ToolResult→`push_tool_result`。cancel 路径（Esc 流式期）也 bump generation（关闭 stale 窗口）

**4d. `main.rs`** — `unbounded_channel::<(u64, AgentEvent)>()`；`App::new` 传 cwd

**4e. `views/chat.rs`** — 遍历 `entries`：`[user]/[assistant]`（原样）、`[tool] name(args截断)` + `▶`（待结果）、`  → output截断`（ok 绿/err 红）、`[system]`（muted）。流式 buffer 仍作末尾进行中 assistant 块带 `▌`

### Step 5 — 斜杠命令

**文件**：`app.rs`（Submit 分支 + `handle_slash_command`）

`ChatAction::Submit`：先取 `input.lines().join("\n")`；若 `trim_start().starts_with('/')` → `take_input()` + `handle_slash_command`（不 spawn）；否则 `submit()` + `spawn_agent`。命令：`/help`、`/clear`（`chat.clear()`）、`/mode [name]`、`/model [name]`（查 `self.providers.providers`，设 `default_provider`）、`/tools`（列 `builtin_tool_names()`）、`/cancel`（abort+bump gen+cancel_stream）、`/quit`、未知→toast

### Step 6 — Mock 双模 + 集成测试

**文件**：`mock.rs`、`tests/mock_roundtrip.rs`

- `MockProvider::stream(req)`：`req.tools.is_empty()` → 旧 echo 行为；非空 → 若 `messages.last().role==Tool` 发最终文本 `"已通过工具完成请求"`，否则发 `ToolCallDelta(list_dir, {"path":"."})` + `Done`
- 旧 4 测试设 `auto_tool_call=false`（保 echo 断言）；新增 `mock_tool_loop_roundtrip`（`auto_tool_call=true`）断言序列 `Started→ToolCall{list_dir}→ToolResult→Token*→Done`

### Step 7 — 测试 / clippy / 文档

- 全 workspace 测试更新（`Message` 构造器、`(u64,AgentEvent)` 通道、`parse_*_line` Vec 断言、`ChatEntry`）
- `clippy --workspace --all-targets -D warnings`（关注 `run_stream` 参数过多→必要时 `SpawnArgs` 结构或 `#[allow]`；boxed future 生命周期）
- 新增单测：工具累积器（喂片段序列→组装 ToolCall）、护栏 denylist、各内置工具、斜杠命令解析
- `PROGRESS.md` §2.6 勾选；`lib.rs` doc 去掉"工具调用留 P2.2"

## 风险点（按序）

1. **Anthropic tool 序列化 + Role::Tool 翻译**（`anthropic.rs`）— content 数组 `tool_use`/`tool_result` 块格式 + 严格 tool_use→tool_result 配对；agent loop 保证顺序，但翻译易错
2. **Step 4 签名互锁** — run_stream(gen)/通道类型/App::new/handle_agent_event/main 同步改，任一类型不匹配即全断
3. **无状态 parser→Vec** — 触碰 HttpStream 状态机 + 3 个 parser 及测试；Anthropic 块 index 命名空间与 text 共享（靠事件类型路由隔离，须文档化不变量）
4. **ToolCallDelta 累积正确性** — index 合并错位/丢片段→arguments JSON 畸形→工具失败；须单测覆盖
5. **Mock 行为变更破坏旧测试** — 用 `tools.is_empty()` 双模 + 旧测试设 `auto_tool_call=false` 规避
6. **Tool::run 对象安全**（无 async-trait）— `Pin<Box<dyn Future+Send+'a>>` + `&'a self`/`&'a ToolCtx` 生命周期须编译；若摩擦大退回 async-trait（加 workspace dep）
